Club 社区平台 | 微服务架构演进与全栈开发
项目背景：本项目是一个从单体转向微服务架构的社区平台。在二、三期迭代中，我主导了系统架构的微服务化拆分、高并发模块优化以及自动化运维体系的搭建，旨在解决业务耦合严重、数据一致性风险及部署效率低下等核心痛点。

🛠️ 核心架构演进 (Architecture Evolution)
1. 微服务化与领域驱动设计 (DDD)
架构拆分：基于微服务领域拆分思想，将原有臃肿逻辑解耦为 4 个核心微服务。

职责清晰化：在三期中进一步将三层架构重构为 api（外部接入层）与 server（内部逻辑层），实现了对内、对外接口的彻底解耦，提升了代码的复用性与可测试性。

服务治理：采用 Nacos 作为注册中心与配置中心，实现服务的自动发现与动态配置切换（无需重启服务即可生效）。

2. 安全与鉴权体系重构
方案选型：弃用繁琐的 Spring Security，选取 Sa-Token 作为鉴权框架，在保证功能闭环的前提下，开发效率提升了近 40%。

网关安全：利用 Spring Cloud Gateway + Redis 实现了分布式会话共享与统一鉴权，并在网关层通过全局异常处理机制拦截非法请求，保障了微服务集群的安全性。

🚀 技术难点与深度优化 (Technical Highlights)
1. 异步化与数据一致性（RocketMQ 实践）
痛点：原有点赞功能直接读写 Redis，存在服务器宕机后数据丢失的风险。

解决方案：引入 RocketMQ 异步处理点赞业务。通过消息持久化机制确保点赞数据的可靠性，同时降低了主业务流程的响应延时。

2. 复杂业务建模与并发编排（效率提升）
业务落地：负责“练题模块”从 0 到 1 的落地，涵盖需求分析、数据建模及接口实现。

线程编排：针对多线程逻辑混乱、难以维护的问题，引入 asyncTool 框架。通过可视化/声明式的线程编排，实现了异步任务的解耦与执行顺序的精准控制。

3. 高质量代码设计（设计模式）
解耦实践：

工厂模式 + 策略模式：重构微信消息处理逻辑，支持不同类型消息（文本、图片、事件）的灵活扩展，彻底消除冗长的 if-else。

适配器模式：通过统一接口适配多云厂商的 OSS 服务，实现存储介质的无感切换。

沉淀复用：将微信对接逻辑抽象为独立的微服务，封装通用 SDK，实现了业务逻辑与三方平台对接逻辑的完全隔离。


🔧 自动化运维与开发工具链 (DevOps)
维度,解决方案,价值体现
持续集成,Jenkins + Shell,解决手动推包部署的低效问题，实现多机器一键自动部署。
容器化,Docker + 数据挂载,中间件全面容器化，通过数据挂载确保配置与数据的持久化。
生产环境,独立部署,独立负责生产环境（云服务器）从系统加固、中间件安装到集群调优的全流程。
开发效率,元数建模 + EasyCode,建立“模型驱动开发”流程，大幅减少样板代码编写量，专注核心逻辑。


📈 项目成果总结
性能提升：通过 RocketMQ 异步化及 asyncTool 编排，核心业务吞吐量显著提升。

交付速度：通过 EasyCode 代码生成与统一 SDK 封装，新功能开发周期缩短。

系统稳定性：引入网关统一异常处理与分布式鉴权，系统崩溃率与非法访问风险大幅降低。
